================================================================================
HARNESS NOTE — how the image was attached
================================================================================
The browser-automation harness cannot drive the macOS native file-picker, and
synthetic Cmd+V does not carry OS clipboard image data into the page. The file
was therefore placed into Open WebUI's own hidden <input type="file"> via a
DataTransfer built from a loopback fetch, then a normal 'change' event was
dispatched — i.e. exactly the DOM path a real drag-and-drop or file-picker
selection produces. Everything downstream of that event (upload, encoding,
transport to Hermes, routing to Qwen-A, rendering) is the unmodified product
path. A human user attaches the file by drag-and-drop, paste, or the "+" button.

WHAT THIS SESSION DOES NOT SHOW
================================================================================
Dangerous-command approval. Hermes advertises approval_events and
run_approval_response on /v1/capabilities, but those live on the Runs API
(/v1/runs/{id}/events), not on /v1/chat/completions, which is what Open WebUI
speaks. A destructive command started from the browser has nobody to ask: it
waits out approvals.timeout (300 s) and is then DENIED. Fail-closed, but a
five-minute stall. Destructive work belongs in `hermes-localchat chat`, where
the arrow-key approval dialog exists.
